# Accordion (React)

The React version of the Test Design System **Accordion** item (Figma component set **collapse**). It renders the same markup and uses the same `accordion.css` and tokens as the HTML component, so it looks identical. The Figma specification tables (anatomy, formatting, alignment) are on the HTML page of this component, **Components / Accordion / collapse**, in the HTML Storybook.

```tsx
import { Accordion } from 'test-design-system';

<Accordion
  title="Do changes to my membership affect my billing cycle?"
  subtitle="Billing"
  leftIcon
  link="Learn more"
  defaultOpen
  onOpenChange={(open) => track(open)}
>
  Your billing cycle does not change.
</Accordion>
```

## Behavior and accessibility

Figma defines a single item that is either closed or open. It does not define a group, so each item opens and closes on its own and opening one does not close another.

- **Click the header, Enter or Space** on the focused header toggles the item. The whole header row, padding included, is the target.
- **Chevron:** points down when closed and up when open, and always matches the state.
- **Content:** shown only when the item is open. It stays in the DOM while closed (hidden), so state inside it is kept.
- **Tab:** the header is focusable. The Button and the link are separate controls with their own focus stops, and clicking them does not toggle the item.
- **Semantics:** the header is a native `button` with `aria-expanded`, and `aria-controls` points to the panel. The panel is a `region` labelled by the title. Ids come from `useId`.
- **Focus:** Figma does not specify a focus appearance, so a focused header shows the existing `shadow-focus-primary` ring on `:focus-visible`.

The HTML component also fires a `ds-accordion-toggle` DOM event. The React component does not: use `onOpenChange`.

Nested accordions, animation, exclusive expansion and extra header actions are not defined in Figma and are not built.

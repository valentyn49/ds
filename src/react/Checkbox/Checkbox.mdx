# Checkbox (React)

The React version of the Socrates **Checkbox**. It renders the same markup and uses the same `checkbox.css` and tokens as the HTML component, so it looks identical. Source of truth: Figma component set **checkbox** (Checkbox page). The Figma specification tables (anatomy, formatting, alignment) are on the HTML page of this component, **Components / Checkbox / checkbox**, in the HTML Storybook.

```tsx
import { Checkbox } from '@socrates/design-system';

<Checkbox
  title="Send me market alerts"
  subtitle="You can change this later."
  checked={alerts}
  onChange={(event) => setAlerts(event.target.checked)}
/>
```

Figma's `state` is not a prop: `selected` is `checked`, `disabled` is the native `disabled`, and `hover` is the browser's `:hover`.

## States

Four values of the Figma `state` property: default, hover, selected and disabled. Hover is forced here with a documentation-only attribute (`rootProps={{ 'data-preview-state': 'hover' }}`); in a page it comes from the browser.

<Canvas of={CheckboxStories.States} sourceState="none" />

Figma does not define an indeterminate state, a focus state, an error state, a hover look for a checked box, or a disabled unchecked box, so none of them have a documented appearance.

## Behavior and accessibility

The component is a native `input type="checkbox"` inside a `label`, so these behaviors come from the browser.

- **Click the box or the label:** toggles the value.
- **Tab:** moves keyboard focus to the checkbox. **Space** toggles it.
- **Disabled:** the checkbox cannot be focused or toggled.
- **Names:** the input is labelled by the title (`aria-labelledby`) and described by the caption (`aria-describedby`) when the caption is shown. The drawn box is `aria-hidden`.
- **Focus:** Figma defines no focus look, so a focused checkbox shows the existing `shadow-focus-primary` ring around the box.

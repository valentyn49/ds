# InputTag (React)

The React version of the Socrates **input tag**: a text field that can also hold tags. It renders the same markup and uses the same `input-tag.css` and tokens as the HTML component, so it looks identical. Source of truth: Figma component set **input tag** (Inputs page). The anatomy, the Figma spec tables and the HTML documentation are on the HTML Storybook page **Inputs / input tag**.

```tsx
import { InputTag } from '@socrates/design-system';

<InputTag
  label="Your email"
  placeholder="Au"
  tags={['Australia BMK']}
  onChange={(event) => setText(event.target.value)}
/>
```

## States

The Figma property `state` has five values: `Default`, `focus`, `filing`, `selected` and `finished`. The border is gray/200 in every state, so they differ by tags, text colour and caret. The carets of `focus`, `filing` and `selected` are drawn here with a documentation-only attribute; in a page the native caret appears while the field is focused.

## Behavior and accessibility

- The text entry is a native `<input type="text">` with a `<label>` linked through `for`. The footnote is linked with `aria-describedby` (your own `aria-describedby` is added to it).
- Clicking anywhere in the field, or on the label, focuses the text entry. Tab moves focus into and out of it.
- It works **uncontrolled** (`defaultValue`, `onChange`) and **controlled** (`value`, `onChange`).
- The `id` is generated with `useId` unless you pass one.
- Tags are display only. Figma draws a close icon on each tag but defines no removing, adding from the text, or selecting, so none of these exist. They are not announced as controls.
- `finished` hides the text entry visually and keeps it in the page for assistive technology.
- Focus is shown by the native caret only, because Figma keeps the border the same in every state.

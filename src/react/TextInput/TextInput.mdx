# TextInput (React)

The React version of the Socrates **text input**. It renders the same markup and uses the same `text-input.css` and tokens as the HTML component, so it looks identical. Source of truth: Figma component set **input** (Inputs page). The Figma specification tables (anatomy, metrics, typography) are on the **input** page of the HTML Storybook.

```tsx
import { TextInput } from '@socrates/design-system';

<TextInput
  label="Email"
  type="email"
  name="email"
  leftIcon="search"
  footnote="We’ll never share your details."
  value={email}
  onChange={(event) => setEmail(event.target.value)}
/>
```

## Behavior and accessibility

- It is a native `<input>`. Typing, selection, autofill and the soft keyboard behave natively, and it works controlled (`value` + `onChange`) or uncontrolled (`defaultValue`).
- The `<label>` is tied to the input with `for`/`id`. The id comes from `useId` unless you pass `id`.
- With `showLabel={false}` the label text is used as `aria-label`, so the field still has a name.
- The footnote is linked with `aria-describedby` (added to any value you pass). In the `error` state the input has `aria-invalid="true"`.
- Pressing anywhere in the field (the icons or the padding) focuses the text, like the HTML component. A disabled field is skipped.
- Figma defines no focus ring for the field other than the darker border; the text caret is the browser's. No clear button, password toggle or masking exists in Figma, so none is built.

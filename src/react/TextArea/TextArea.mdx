# TextArea (React)

The React version of the Test Design System **text-area**. It renders the same markup and uses the same `text-area.css` and tokens as the HTML component, so it looks identical. Source of truth: Figma component set **text-area** (Inputs page). The Figma specification tables (anatomy, formatting, measurements) are on the HTML page of this component in the HTML Storybook and are not repeated here.

```tsx
import { TextArea } from 'test-design-system';

<TextArea
  label="Comment"
  placeholder="Write something"
  footnote="Visible to your team"
  value={comment}
  onChange={(event) => setComment(event.target.value)}
/>
```

## States

Figma has one variant property, `state`, with seven values: `default`, `focus`, `filing`, `filled`, `disabled`, `valid` and `error`. The first five are the behavior of a native text area: `focus` and `filing` are `:focus-within` (without and with text), `filled` is a field with a value, and `disabled` is the native attribute. `valid` and `error` are set with `validation`. ### Multi-line text

Figma defines no row count, maximum height, resize handle or character counter. The field is one line tall by default and grows with its content in browsers that support `field-sizing`.

## Behavior and accessibility

- It is a native `textarea` with a `label` linked through `for` (the id is generated with `useId` unless you pass `id`). The footnote is linked with `aria-describedby`; a `aria-describedby` of your own is kept and combined.
- **Typing:** Enter inserts a new line. **Tab** moves focus into and out of the field. A click on the label, the icons or the field padding focuses the text area.
- **Disabled:** the field cannot be focused or edited.
- **Error:** sets `aria-invalid` on the text area. Figma defines no combined focus and validation look, so the validation color stays while focused.
- Focus shows the stroke in gray/500 through `:focus-within`; there is no JavaScript state for it.

# Stepper (React)

The React version of the Test Design System **Stepper**: one step of a multi-step progress indicator, such as a sign-up or purchase flow. It renders the same markup and uses the same `stepper.css` and tokens as the HTML component, so it looks identical. Source of truth: Figma component set **stepper** (Stepper page). The Figma specification tables (anatomy, formatting, alignment) are on the HTML page of this component, **Components / Stepper / stepper**, in the HTML Storybook.

```tsx
import { Stepper } from 'test-design-system';

<Stepper state="filled" number="1" title="Choose membership plan" subtitle="Short description" />
<Stepper state="active" number="2" title="Payment" subtitle="Add a card" />
<Stepper state="next step" number="3" title="Confirm" />
```

## States

The four values of the Figma `state` property. They describe where a step is in the sequence, so they are set with the `state` prop rather than by hover or focus. Figma defines no hover, focus, pressed or error look for a step.

## Behavior and accessibility

Figma defines how a step looks in each state but no interaction: there is no click, hover, focus, keyboard or navigation behavior for a step, so the component is presentational and does not move between steps by itself. To keep the progress understandable to assistive technology, these attributes are set from the state:

- **Active:** the step has `aria-current="step"`.
- **Disabled:** the step has `aria-disabled="true"`.
- **Filled:** the check mark replaces the number, so the step also contains the visually hidden text "Completed:" before its title.
- **Connector:** it is decorative and hidden from assistive technology.
- **Overrides:** an `aria-current` or `aria-disabled` you pass replaces the default.

Validation rules, clickable steps or moving to the next step are not defined in Figma and are not built. When you build a flow, put the steps in a list (`role="list"` and `role="listitem"`, as in the sequence above).

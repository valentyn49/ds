# Popup (React)

The React version of the Socrates **Popup** (Figma component set **modal**, backdrop **blur**, frames **480** and **600**, and the Behaviour section). It renders the same markup and uses the same `popup.css` and tokens as the HTML component, so it looks identical. The Figma specification tables (anatomy, basic popup, formatting and alignment, states) are on the HTML page of this component, **Components / Popup / modal**, in the HTML Storybook.

```tsx
import { useState } from 'react';
import { Button, Popup } from '@socrates/design-system';

function Upgrade() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <Button onClick={() => setOpen(true)}>Upgrade</Button>
      <Popup
        open={open}
        title="Premium subscription required"
        onClose={() => setOpen(false)}
        onPrimary={() => startUpgrade()}
      >
        Would you like to upgrade to Premium now?
      </Popup>
    </>
  );
}
```

## Live Demo

Press **Open popup**. This is the real component: it traps focus, makes the page behind it inert, closes with the close control, Cancel and Escape, and returns focus to the button. The primary action does not close it, because that is up to the application. Change a control while the popup is open and the open popup follows.

The **preview** control chooses a desktop, tablet or mobile frame, or opens the popup over this whole page (`viewport`). The frame, the page behind it and the status line belong to the documentation and are not part of the component.

## Responsive layout

The layout follows the width of the popup's container, with the same limits as the Header and Footer: mobile up to 576px, tablet 577 to 992px, desktop from 993px. On desktop the popup is centered, 80px from the top, with Cancel and the primary action on the right. On tablet and mobile it is a bottom sheet with one full-width primary action and no Cancel.

## Behavior and accessibility

- The dialog has `role="dialog"` and `aria-modal="true"`, is named by its title and described by its subtitle (or its body when there is no subtitle).
- On open, focus moves to the dialog; Tab and Shift+Tab stay inside it; everything else in the container is `inert`; the page does not scroll behind a popup that fills the window.
- Escape closes the popup (`closeOnEscape`); with several popups only the topmost reacts. A click on the backdrop does nothing unless `closeOnBackdrop` is set.
- On close, focus returns to the element that had it when the popup opened.
- Close, Cancel and the primary action are three different actions. The close control and Cancel call `onClose`; the primary action only calls `onPrimary`. You decide whether to close, keep the popup open for a next step, or show a loading look (Figma defines none).
- The overlay also dispatches the bubbling DOM events `ds-popup-open`, `ds-popup-primary`, `ds-popup-cancel` and `ds-popup-close` (with `detail.reason`), as the HTML component does. The log below shows them.
- Figma defines no animation, so there is none.

<Canvas of={PopupStories.Behavior} sourceState="none" />

Differences from the HTML component: the popup is declarative, so there is no `open()` / `close()` to call and `onClose` is not called when your code sets `open` to false (you already know). The HTML events for programmatic closes are therefore not dispatched.
